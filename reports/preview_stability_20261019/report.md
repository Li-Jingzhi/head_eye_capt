# 黄球预览闪烁修复与曝光/触发核查（2026-10-19）

## 已修复的问题

原程序把视频推送、2D黄球检测和严格双目配帧绑定：未获得源时间差和回调到达时间差同时≤10ms的新帧对时，既不推送图像，也用没有球心的等待消息覆盖最新检测。结果是画面STALE、椭圆/球心闪现，视觉上像检测或曝光不稳定。

现已改为：

- 左右新鲜图像持续按约12Hz校正并回传，即使当前没有合格严格配对，也能逐眼实时检测黄球。
- 单眼2D预览检测不进行异步双目三角化，显示`YELLOW DETECTED`、当前严格3D采样率及两种时差。
- 只有真正合格双目配对才计算并发布可采集的3D球心，继续执行两项≤10ms门槛、完整椭圆质量和极线检查。
- 采集入口`runtime/yellow_detection/latest.json`仅由PASS消息更新；拒绝/等待状态单独写`latest_status.json`。旧PASS的接收时间不会被刷新，采集器仍检查≤250ms新鲜度和每眼源帧唯一性。
- 显示上最近一次有效3D深度明确标注年龄；超时不保留，不把2D预览或旧深度当成新的3D测量。

35秒复测420次预览，**420/420左右眼都检测到黄球**，预览约11.98FPS，图像与圆心覆盖持续刷新。该轮严格3D仅2次合格，明确说明“2D看起来稳定”不等于同步采样已通过。

2项2D预览回归测试、5项配帧测试和3项机器人采集窗口测试通过。测试覆盖异步/极线不匹配仍可逐眼预览但不能生成3D测量，以及真实球消失后不继续保留假检测。现场截图已检查。

## 曝光是否与旧Orin一致

旧工程最后的`runtime/new_sh5_yellow/latest_status.json`记录`camera_controls=null`、AE/AWB锁定、50Hz防频闪，没有记录实际曝光时间、模拟/数字增益或固定白平衡增益。

新工程与旧正式链采用相同策略：Argus mode0、2560×1984@30，50Hz防频闪，自动适应约5秒后锁AE/AWB；没有擅自设置新的固定曝光值或修改HSV/椭圆质量阈值。

新机GObject回读：AE/AWB均true，防频闪枚举2（50Hz），wbmode1、tnr-mode1、ee-mode1、saturation1；exposuretimerange/gainrange/ispdigitalgainrange没有显式固定值。此类GObject属性是配置值/允许范围，不是逐帧真实传感器曝光元数据。

触发测试恢复后的V4L2驱动读数：左右`exposure=19999`（约20ms），左CSI8`gain=133`、右CSI0`gain=140`。这些是本次新机驱动控制读回；旧机没有对应记录，不能声称新旧曝光/增益数值完全相同。自动适应值会随设备和场景变化。

## 更深层的双目同步问题

在设备上找到厂商驱动包说明：

`/home/marvin/nvidia/SG10A-AGON-G2M-A1/JetPack6.2/SG10A_AGON_G2M_A1_AGX_ORIN_SHW5G_JP6.2_L4TR36.4.3/Readme.md`

厂商第6节明确：`trig_mode=0`不使用触发同步；`trig_mode=1`使用触发同步，但需要外部触发信号接入适配板。说明副本为本目录`vendor_driver_readme.md`。

此前共同GStreamer管线+队列配帧复测95.8%输入覆盖率只适用于那一轮启动；重启后自由运行相位可变化，不能保证每次启动都满足10ms门槛。不能仅凭一个高覆盖率样本宣称硬件同步已经修复。

用户不确定外部触发是否接入，因此进行了可逆对照测试：

1. 停止本项目相机进程。
2. 原始V4L2采集设置bypass_mode=0，在模式0下两眼均收到连续有效GB10帧，帧间隔约33.311ms。
3. 同一原始路径切换模式1：CSI8仅收到错误/零时间戳缓冲，CSI0也出现错误缓冲并超时，未获得有效触发图像流。
4. 恢复两眼trig_mode=0和Argus使用的bypass_mode=1，启动稳定2D预览并重新按原策略锁曝光/白平衡。

第一次未显式调整bypass的探测不能单独判定触发状态；以`trigger_mode_comparison.txt`中的模式0/1对照为依据。模式1未出有效图像只证明当前条件下外部触发不可用，不能区分未接线、源未输出、接线/电平/频率不匹配或其他配置问题。

**当前未检测到可用的外部触发条件，因此不能保证持续稳定的严格3D采样。** 需要确认适配板触发接线、共同信号源和厂商允许的电平/频率后再启用模式1；没有猜测接线、设置未经确认的触发输出，或放宽时间门槛。

192.168.12.190已只读确认SDK/控制器00040701，双7轴、head/body0自由度，右ARM1的32项MDH与`configs/1004.ini` R.A1一致。无头姿采集的新示教/回放入口已经适配并测试：3deg示教点、5deg相邻步限、5%逆序回放、每停稳位置50个唯一有效帧。

当前严格视觉采样率不足，尚未启动拖动示教或自动回放，没有发送机器人模式切换/运动指令。`pro_capture --check`和正式入口均要求5秒内25个唯一PASS观测通过预检；不满足时阻止进入拖动模式。
